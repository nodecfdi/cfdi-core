`@nodecfdi/cfdi-core` incluye tres descubridores listos para identificar la versión de documentos fiscales del SAT sin depender de un formato de entrada único. Si no encuentran una versión coincidente, devuelven una cadena vacía `''`.

## Descubridores disponibles

| Clase | Documento | Versiones detectadas | Atributo evaluado |
| --- | --- | --- | --- |
| `CfdiVersion` | CFDI | `'4.0'`, `'3.3'`, `'3.2'` | `Version` (4.0/3.3) o `version` (3.2) |
| `TfdVersion` | Timbre Fiscal Digital | `'1.1'`, `'1.0'` | `Version` (1.1) o `version` (1.0) |
| `RetencionVersion` | CFDI de Retenciones | `'2.0'`, `'1.0'` | `Version` |

## Formas de uso

Todos los descubridores heredan de `VersionDiscoverer` y ofrecen los mismos métodos de entrada:

- `getFromXmlString(contents)`: Parsea la cadena XML y evalúa el elemento raíz.
- `getFromNode(node)`: Evalúa un `XmlNodeInterface`.
- `getFromDOMElement(element)`: Evalúa un `Element` de `@xmldom/xmldom`.
- `getFromDOMDocument(document)`: Evalúa el elemento raíz de un `Document` de `@xmldom/xmldom`.
- `discover(container)`: Evalúa cualquier implementación de `ContainerWithAttributeInterface`.

```ts [descubrir-versiones.ts]
import {
  CfdiVersion,
  nodeFromXmlString,
  RetencionVersion,
  TfdVersion,
} from '@nodecfdi/cfdi-core';

const cfdiXml = '<cfdi:Comprobante Version="4.0"/>';
const cfdiVersion = new CfdiVersion().getFromXmlString(cfdiXml);
console.log(cfdiVersion); // '4.0'

// Desde un XmlNode existente (ej. un nodo hijo del complemento)
const tfdNode = nodeFromXmlString('<tfd:TimbreFiscalDigital Version="1.1"/>');
const tfdVersion = new TfdVersion().getFromNode(tfdNode);
console.log(tfdVersion); // '1.1'

// Para Retenciones
const retVersion = new RetencionVersion().getFromXmlString(
  '<retenciones:Retenciones Version="2.0"/>',
);
console.log(retVersion); // '2.0'
```
